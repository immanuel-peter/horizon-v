# Step 8: Stage 2, projector-only GRPO

Start from the SFT checkpoint and train only the projector with GRPO in upstream Miles. [Step 4](04-gate-checks.md) validated its FSDP precision/packing and native projector-update/cache components on one SM120 GPU. An end-to-end GRPO, reward and recovery cycle has not run. Complete the checks below before a long run.

## 1. Scorer contract

Adapt and test the selected RL360 scorers before launching. Its [`async_rm`](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/src/miles360/reward/__init__.py) selects by `sample.metadata.data_source` and compares `sample.response` with `sample.label`; it does not inspect images.

Points to settle:

- **Selector, not provenance.** `data_source` picks the scorer ([step 5](05-data.md): `math_dapo` for numeric/symbolic, `stem__supergpqa` for choice). Record the original dataset separately. An unsupported source must raise or return an explicit failure, never a silent zero. The exact selector `hiyouga/geometry3k` would route to `geo3k`, so Geometry3K rows need the selector set deliberately.
- **Format reward.** [`geo3k.compute_score`](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/src/miles360/reward/geo3k.py) gives 10% credit for literal `<think>...</think>` plus a boxed answer. That component cannot pass on K2's answer-only text. The planned `math_dapo` selector avoids it. If adopting Geo3K, choose correctness-only scoring or a separate K2-compatible format term explicitly.
- **Reasoning versus answer.** Score the text after the closing think tag so a `\boxed{}` inside the reasoning does not count. An unclosed think block receives zero reward as a policy-format failure; do not silently discard it as an infrastructure failure.

Required tests per selected scorer: correct, wrong and equivalent answers, a box inside reasoning versus in the final answer, each of the three close tags, missing close tag, malformed output, timeout, and unsupported `data_source`. Pull in only the scorers' dependencies (`mathruler` and a timeout helper for Geo3K, for example).

## 2. Failures and the group filter

RL360's Miles fork has two filters that behave differently, in [`dynamic_sampling_filters.py`](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/components/miles/miles/rollout/filter_hub/dynamic_sampling_filters.py). `check_valid_reward_nonzero_std` leaves aborted, infrastructure-failed, judge-failed and missing-reward attempts out of the variance calculation. `check_reward_nonzero_std` rejects a group that has a missing reward. They are not renames.

Keeping a group does not show that its invalid members are excluded from the loss. Before relying on either filter, read the pinned upstream Miles caller, filter and loss code, then test with injected failures: a failed image fetch, an engine abort, a scorer exception and a truncated reasoning block. Show for each whether the attempt is dropped, scored zero or trained on, and make that the intended behavior.

## 3. Prompt selection

Follow the sampling protocol in [step 5](05-data.md), counting complete valid attempts without optimizer steps. Adapt RL360's [`calibration.py`](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/src/agent360/harbor/miles/calibration.py) from Harbor task/coding-verifier records to image prompts and the chosen scorers. Its pass-rate band is a starting protocol, not a measured optimum for projector-only RL.

## 4. Update-cycle test

The loader and cache gates show that the engine accepts a projector-only update and invalidates cached features. They do not exercise Miles's GRPO loop. Before long training, run a short job and show all of:

1. Image rollout through SGLang, then reward, then an FSDP projector update.
2. A projector-only sync to the running engine (six trainable tensors, cache flushed, frozen digests unchanged). IFM's experimental FSDP [weight updater](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/components/miles/miles/backends/experimental/fsdp_utils/update_weight_utils.py) sends the full state dict, so the pinned Miles weight iterator needs a projector-only change or a verified equivalent. Do not assume stock behavior.
3. Changed image features on the updated engine, and equivalence with a fresh engine started from the exported checkpoint.
4. Train-versus-rollout logprob metrics. TIS ([`loss.py`](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/components/miles/miles/backends/training_utils/loss.py)) clamps `exp(train_logprob - rollout_logprob)` and multiplies the policy loss, separately from PPO clipping. It is a correction for small mismatches and does not repair wrong image inputs or HF/SGLang parity, so the gap metric must stay small without it.

For recovery, compare an uninterrupted run with a save, restart and continue, checking weights, optimizer, scheduler, RNG, rollout index and the next update. IFM's experimental [checkpoint code](https://github.com/ifm-ai/RL360/blob/3e13010e0e47b7d08f19dfb6bdd3ac6d21dc200e/components/miles/miles/backends/experimental/fsdp_utils/checkpoint.py) can skip an optimizer or scheduler that fails to load. Treat a missing required state as a failure.

## 5. Launch settings (proposed)

These are starting points from IFM's text coding recipe, not validated for projector-only vision RL. Adapt the flags to the pinned Miles at `third_party/miles` and to the registration variables in `tools/step04/miles_sft.sh`. Copy that script's `SGLANG_EXTERNAL_*`, attention and `--true-on-policy-mode` choices, which are what the gates validated, and do not copy its SFT loss flags.

| Setting | Starting value | Basis |
|---|---|---|
| Advantage | GRPO, no std normalization | RL360 `recipes/coding-overfit32.sbatch:111-124` |
| Importance sampling | TIS | same |
| Clip | 0.2 / 0.28 | same |
| KL, entropy | 0 | same; no reference model needed |
| Optimizer | Adam, β 0.9 / 0.98, WD 0.1, constant LR | same |
| LR | 1e-5 | Guess, ~100× below SFT. RL360 used 5e-6 for full-model RL. Sweep it. |
| Group filter | per section 2 | |
| Samples | 8 per prompt, 8192 max response | Unmeasured. Size from the response-length measurement below. |

Projector-only LR, clip, KL and weight decay are all open. Sweep LR first. Keep `--apply-chat-template` with `reasoning_effort` set in `--apply-chat-template-kwargs` for RL prompts (generation, unlike SFT), and use one effort for prompt selection, training and eval.

Size the trainer/engine split from measured throughput and memory on the target GPUs. The frozen LM still needs activation backward to train the projector. Gate numbers (22.4 GB native, 44.4 GB SFT) apply only to the gate's TP=1, 2048-context profile.

## Reasoning effort

Measure K2's thinking length on the filtered RL prompts with the SFT checkpoint. If high effort routinely runs far past the response limit, try medium. Do not assume the saving.

## Monitor

| Metric | Healthy |
|---|---|
| Reward | Rising, then plateau |
| Response length | Track distribution and investigate a collapse |
| Train vs rollout logprob gap | Small and flat |
| Think-close rate | Near 100% |
| Invalid-attempt rate | Low, tracked by cause (image, engine, scorer, truncation) |
| [Step 7](07-eval.md) evals, periodically | Above the SFT baseline |

Stop when held-out evals plateau. Export as in [step 6](06-sft.md#export): the init repo with the new projector tensors, verified against the trained checkpoint.
