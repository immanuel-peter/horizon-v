# RL360

[ifm-ai/RL360](https://github.com/ifm-ai/RL360) is IFM's RL stack for K2-Horizon (commit `3e13010`). It has no vision code, its K2 recipe is Megatron-only, and its Miles fork keeps FSDP under `backends/experimental/` in an older form than upstream. Keep upstream Miles; borrow the pieces below.

GRPO settings:

```bash
--advantage-estimator grpo --disable-grpo-std-normalization --use-tis
--eps-clip 0.2 --eps-clip-high 0.28 --kl-loss-coef 0 --entropy-coef 0
--optimizer adam --adam-beta1 0.9 --adam-beta2 0.98 --weight-decay 0.1 --lr-decay-style constant
--dynamic-sampling-filter-path miles.rollout.filter_hub.dynamic_sampling_filters.check_reward_nonzero_std
```

- RL360's LR is 5e-6 for full-model RL. Sweep the projector-only LR separately.
- The filter is named `check_valid_reward_nonzero_std` in RL360 and `check_reward_nonzero_std` upstream.

## Confirms

`K2V3TITOTokenizer` (`components/miles/miles/utils/chat_template_utils/tito_tokenizer.py:347`) documents that K2's template renders append-only:

- nothing between `<|ifm|im_end|>` and the next `<|ifm|im_start|>`;
- no byte after the stop token.

This makes the prefix/suffix split in the SFT rollout safe ([step 6](../steps/06-sft.md)). The class itself is only needed for multi-turn or agentic rollouts.

## Ignore

- Harbor, SMG, sandboxes and session servers: agentic coding RL.
- The 33-node recipe scale.
- `recipes/k2-horizon-7b.json`: Megatron architecture args. It does confirm grouped RMSNorm with 4 groups, which the text-parity check covers.
- `merge360`: could average several projector RL runs later. Optional.
